# Profile Rules

**Stable facts about the user. Travels with the person — not with the tool, not with the project.**

## 1. What Belongs Here

- What shaped the gaps — not a résumé.
- The uneven map of strengths and holes.
- How the user wants to be worked with, and why each preference exists.

**Does not belong here:**

| Statement | Home |
| --- | --- |
| Who executes what in this project | the mode table — `.agents/AGENTS.md` |
| Anything that expires | nowhere |
| Anything a session inferred and nobody confirmed | nowhere — propose it |

**One exception to "anything that expires":** a habit the person is actively recalibrating. It is
written down *because* it is meant to expire — mark it as such, and drop it once it has.

**The test:** if it stops being true when the project changes, it is not profile.

## 2. Never Infer Level by Topical Adjacency

**Adjacent topics are not evidence.** Depth in one area predicts nothing about the one beside it.

Before leaning on one thing to explain another, check the map — or ask.

If the profile file is missing, say so. Do not fill the gap by inference.

## 3. Not Written by Inference

- A session does not update this file. It proposes; the user decides.
- Same rule as `docs-archive/`, same reason: the agent is not the authority on the user.

## 4. Read It, Don't Quote It Back

It calibrates the answer. It is never recited at the user, and never copied into a doc, an issue,
or a commit. Using it well is invisible.

## 5. Loaded, Not Read

**A profile that has to be opened is a profile nobody opens.**

This file is the canonical source. Its content belongs in whatever the tool loads on its own, and
is copied there. No contract can force a read — do not write one that pretends to.
